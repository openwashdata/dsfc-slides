Quarto refresher

The three components of a .qmd file

  • YAML header: metadata and options between --- fences at the top
  • Markdown text: headings, prose, lists, links
  • Code chunks: executable R code between ```{r} fences

Quarto runs the chunks, weaves the results into the text, and renders everything to HTML, PDF, or slides.

The YAML header

---
title: "My analysis"
author: "Adriana"
date: "2026-06-04"
format: html
execute:
  echo: true
---

Indentation matters in YAML. Two spaces, never tabs.

Code chunk options

Options go inside the chunk, each on its own line starting with #|:

```{r}
#| label: my-chunk
#| echo: true
#| warning: false

mean(c(1, 2, 3))
```

The most useful chunk options

Option Effect
label names the chunk, useful for navigation and finding errors
echo show the code itself
eval run the code
include show code output
warning show warnings
message show messages
error render even if the chunk errors

Options for cross-references

Remember from module 5: two options turn a chunk’s output into a numbered, linkable table or figure.

```{r}
#| label: fig-height-mass
#| fig-cap: "Height vs mass of Star Wars characters"

starwars |>
  ggplot(aes(height, mass)) +
  geom_point()
```
  • label must start with fig- (figures) or tbl- (tables)
  • Pair it with fig-cap or tbl-cap
  • Refer to it in the text with @fig-label or @tbl-label. In the example above: @fig-height-mass

Data types in R

The four basic types

Every value in R has a type.

Type Examples
character "hello", "42"
integer 1L, 42L
double 1.5, 42, pi
logical TRUE, FALSE, NA

integer and double are the numeric types.

Checking the type with typeof()

typeof("hello")
[1] "character"
typeof(1L)
[1] "integer"
typeof(1.5)
[1] "double"
typeof(TRUE)
[1] "logical"

Integer or double?

A plain number is a double by default, even without decimals:

typeof(42)
[1] "double"

The L suffix asks for an integer explicitly:

typeof(42L)
[1] "integer"
typeof(1:10)
[1] "integer"

Sequences made with : are integers. In practice the difference rarely matters; R converts between them silently.

Coercion: mixing types

A vector can hold only one type. When you mix, R converts everything to the most flexible type:

c(1, "two", TRUE)
[1] "1"    "two"  "TRUE"
c(1, TRUE, FALSE)
[1] 1 1 0

The hierarchy: logical → integer → double → character.

This is why a single text entry in a spreadsheet column can turn a whole column of numbers into text after import.

Explicit conversion

The as.*() family converts on demand:

as.numeric("3.14")
[1] 3.14
as.character(42)
[1] "42"
as.integer(TRUE)
[1] 1

Impossible conversions give NA with a warning:

as.numeric("hello")
Warning: NAs introduced by coercion
[1] NA

Data classes

Type vs class

typeof() tells you how a value is stored.

class() tells you how a value behaves.

d <- as_date("2026-06-04")
typeof(d)
[1] "double"
class(d)
[1] "Date"

A Date is stored as a double (days since 1970), but its class makes it print and compute like a calendar date.

The factor class

A factor represents a categorical variable: a value that can only take one of a fixed set of levels.

sizes <- factor(c("small", "large", "small", "medium"))
sizes
[1] small  large  small  medium
Levels: large medium small
levels(sizes)
[1] "large"  "medium" "small"

How factors are stored

Under the hood, a factor is an integer vector plus a table of levels:

typeof(sizes)
[1] "integer"
class(sizes)
[1] "factor"
as.integer(sizes)
[1] 3 1 3 2

Why bother with factors?

  • Plots and tables follow your order, not the alphabet
  • Levels with zero observations still show up in counts
  • Typos become visible: a fifth level you did not expect
  • Models need them to treat a variable as categorical

Vectors vs lists

Atomic vectors

The vectors we have used so far are called atomic: every element has the same type.

heights <- c(172, 167, 96, 202)
heights
[1] 172 167  96 202

That uniformity is what makes vectorized operations possible:

heights / 100
[1] 1.72 1.67 0.96 2.02

Lists

A list can hold anything: different types, different lengths, even other lists.

person <- list(
  name    = "Luke",
  height  = 172,
  films   = c("A New Hope", "Return of the Jedi")
)
str(person)
List of 3
 $ name  : chr "Luke"
 $ height: num 172
 $ films : chr [1:2] "A New Hope" "Return of the Jedi"

Vector or list?

Atomic vector

  • One type for all elements
  • Elements are single values
  • Built with c()
  • Fast, vectorized math

List

  • Each element can differ
  • Elements can be whole vectors
  • Built with list()
  • The flexible container

str() is your friend: it shows the structure of any object at a glance.

Building data frames

From vectors to a data frame

A data frame is a list of vectors of equal length, displayed as columns.

Two ways to build one from vectors:

  • data.frame() from base R
  • tibble() from the tidyverse

With base R: data.frame()

df <- data.frame(
  name   = c("Luke", "Leia", "R2-D2"),
  height = c(172, 150, 96),
  droid  = c(FALSE, FALSE, TRUE)
)
df
   name height droid
1  Luke    172 FALSE
2  Leia    150 FALSE
3 R2-D2     96  TRUE

With the tidyverse: tibble()

tb <- tibble(
  name   = c("Luke", "Leia", "R2-D2"),
  height = c(172, 150, 96),
  droid  = c(FALSE, FALSE, TRUE)
)
tb
# A tibble: 3 × 3
  name  height droid
  <chr>  <dbl> <lgl>
1 Luke     172 FALSE
2 Leia     150 FALSE
3 R2-D2     96 TRUE

A tibble is a data frame, with a few surprising behaviours removed.

data.frame() vs tibble()

Behaviour data.frame() tibble()
Printing everything first 10 rows, types shown
Recycling any length that divides evenly only length 1
Column names “fixes” them, my var → my.var keeps them as written
Use a column just defined no yes

Accessing columns

Four ways to reach a column

tb <- tibble(
  name   = c("Luke", "Leia", "R2-D2"),
  height = c(172, 150, 96)
)
Syntax Returns
tb$height a vector
tb[["height"]] a vector
tb["height"] a tibble with one column
pull(tb, height) a vector, pipe-friendly

$ and [[: get the vector

tb$height
[1] 172 150  96
tb[["height"]]
[1] 172 150  96

[[ also works with a position or a variable holding the name:

tb[[2]]
[1] 172 150  96
col <- "height"
tb[[col]]
[1] 172 150  96

[: keep the data frame

Single brackets subset the data frame, so you get a data frame back:

tb["height"]
# A tibble: 3 × 1
  height
   <dbl>
1    172
2    150
3     96

tb["height"] will not work where a plain vector is expected, for example mean(tb["height"]) returns an error while mean(tb[["height"]]) and mean(tb$height) work as expected.

pull(): the pipe-friendly extractor

pull() does what $ does, but fits at the end of a pipeline:

starwars |>
  filter(species == "Droid") |>
  pull(height)
[1] 167  96  97 200  96  NA

Compare with select(), which keeps the data frame structure:

starwars |>
  filter(species == "Droid") |>
  select(height)
# A tibble: 6 × 1
  height
   <int>
1    167
2     96
3     97
4    200
5     96
6     NA

For loops

When you need repetition

Much of R is vectorized, so many loops written in other languages are one line here.

But sometimes you genuinely need to repeat a computation: once per file, once per column, once per simulation.

That is what a for loop does.

The anatomy of a for loop

for (item in vector) {
  # body: runs once per element,
  # with `item` set to the current element
}
  • item: a name you choose for the current element
  • vector: the values to iterate over
  • body: the code to repeat, inside { }

A first loop

names <- c("Luke", "Leia", "R2-D2")

for (n in names) {
  print(n)
}
[1] "Luke"
[1] "Leia"
[1] "R2-D2"

Inside a loop, results are not printed automatically. Use print() to see them.

Looping over positions

Often you want the index, not the value. Use seq_along():

heights <- c(172, 150, 96)

for (i in seq_along(heights)) {
  print(heights[i] / 100)
}
[1] 1.72
[1] 1.5
[1] 0.96

Collecting results

Create an output container first, then fill it position by position:

heights <- c(172, 150, 96)
heights_m <- vector()

for (i in seq_along(heights)) {
  heights_m[i] <- heights[i] / 100
}

heights_m
[1] 1.72 1.50 0.96

Looping over columns

A data frame is a list, so you can loop over its columns:

tb <- tibble(height = c(172, 150, 96), mass = c(77, 49, 32))
means <- vector("double", ncol(tb))

for (i in seq_along(tb)) {
  means[i] <- mean(tb[[i]])
}

means
[1] 139.33333  52.66667

Note the [[: each column comes out as a plain vector.

Loop or vectorize?

  • If a vectorized function exists, use it: heights / 100 is faster than a loop
  • Loops shine when steps depend on each other, or for side effects like saving one file per group
