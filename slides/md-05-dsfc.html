Logical vectors and comparisons

Logical values

R has a third atomic type alongside numbers and text: logical.

Two possible values, TRUE and FALSE (plus NA for unknown).

c(TRUE, FALSE, TRUE)
[1]  TRUE FALSE  TRUE

T and F work but are not reserved words, so they can be overwritten. Always write the full TRUE and FALSE.

Why logical vectors matter

Most data questions reduce to:

  • Which rows match a condition?
  • Which values are missing?
  • Where is the price above 1000?

The answer is a logical vector you can pass to filter(), if_else(), or case_when().

Comparison operators

Operator Meaning
< less than
<= less than or equal to
> greater than
>= greater than or equal to
== equal to
!= not equal to

A single = is for assignment in function calls. Equality is ==.

Comparisons are vectorized

The comparison runs element by element:

x <- c(2, 5, 9, 12)
x > 5
[1] FALSE FALSE  TRUE  TRUE

Recycling kicks in if one side is shorter:

y <- c(1, 6, 8, 10)
x > y
[1]  TRUE FALSE  TRUE  TRUE

Equality with decimals

== on doubles can surprise you:

0.1 + 0.2 == 0.3
[1] FALSE

Use near() for numerical equality:

near(0.1 + 0.2, 0.3)
[1] TRUE

Missing values and is.na()

NA is contagious. Any comparison with NA returns NA, not TRUE or FALSE:

NA == NA
[1] NA
NA > 5
[1] NA

To test for missingness, use is.na():

x <- c(1, NA, 3, NA)
is.na(x)
[1] FALSE  TRUE FALSE  TRUE

Membership with %in%

%in% tests whether each value on the left appears anywhere on the right.

species <- c("Droid", "Human", "Wookiee", "Droid")
species %in% c("Human", "Wookiee")
[1] FALSE  TRUE  TRUE FALSE

It is the readable alternative to chaining == with |:

species == "Human" | species == "Wookiee"

Combining conditions

Operator Meaning
& AND, element by element
| OR, element by element
! NOT 
x <- c(2, 5, 9, 12)
x > 3 & x < 10
[1] FALSE  TRUE  TRUE FALSE

Conditional values

From a condition to a value

A comparison gives you a vector of TRUE and FALSE.

Often you want to go one step further and assign each row a different value depending on the answer.

That is what if_else() and case_when() are for.

if_else()

if_else(condition, true, false, missing = NULL)
  • condition: a logical vector
  • true: value returned where the condition is TRUE
  • false: value returned where the condition is FALSE
  • missing: optional value used where the condition is NA

if_else() in action

starwars |>
  mutate(size = if_else(height > 180, "tall", "short")) |>
  select(name, height, size) |>
  head(4)
# A tibble: 4 × 3
  name           height size 
  <chr>           <int> <chr>
1 Luke Skywalker    172 short
2 C-3PO             167 short
3 R2-D2              96 short
4 Darth Vader       202 tall

if_else() is type-strict

The true and false branches must return the same type.

if_else(c(TRUE, FALSE), "yes", 0)
Error in `if_else()`:
! Can't combine `true` <character> and `false` <double>.

This is a feature, not a bug. Base R’s ifelse() is more forgiving but can silently change types.

case_when()

When you need more than two outcomes, nested if_else() becomes unreadable.

case_when() handles multiple conditions in a flat, ordered list:

case_when(
  condition_1 ~ value_1,
  condition_2 ~ value_2,
  ...
  .default = fallback
)

Reading case_when()

For each row, R checks conditions from top to bottom and returns the value next to the first TRUE.

starwars |>
  mutate(
    size = case_when(
      height < 150 ~ "small",
      height < 200 ~ "medium",
      height >= 200 ~ "large"
    )
  ) |>
  select(name, height, size) |>
  head(4)
# A tibble: 4 × 3
  name           height size  
  <chr>           <int> <chr> 
1 Luke Skywalker    172 medium
2 C-3PO             167 medium
3 R2-D2              96 small 
4 Darth Vader       202 large

.default and the catch-all

x <- c(-1, 5, 12, NA)
case_when(
  x < 0  ~ "negative",
  x < 10 ~ "small",
  x >= 10 ~ "large",
  .default = "unknown"
)
[1] "negative" "small"    "large"    "unknown"

Anything not matched by an explicit condition (including NA) falls into .default. Without it, those values become NA.

Order matters

case_when() evaluates conditions in order. Put the most specific ones first:

age <- c(2, 15, 40, 70)
case_when(
  age < 13 ~ "child",
  age < 20 ~ "teenager",
  age < 65 ~ "adult",
  .default = "senior"
)
[1] "child"    "teenager" "adult"    "senior"

If age < 65 came first, everyone under 65 would end up as adult.

Dates and times

Why dates are tricky

  • Different written formats, 2026-06-04 vs 04/06/2026 vs June 4, 2026
  • Time zones and daylight saving time
  • Leap years (and leap seconds)
  • 30 vs 31 days in a month
  • Storing dates as text loses arithmetic

R has dedicated types so you can do real date math.

R’s date types

Type What it stores Created with
Date a calendar date as_date(), ymd()
POSIXct a date-time, seconds since 1970 as_datetime(), ymd_hms()
POSIXlt a date-time as a list of components as.POSIXlt()

In daily use you will mostly meet Date and POSIXct.

The reference moment

R stores a Date as the number of days since 1970-01-01.

d <- as_date("2026-06-04")
d
[1] "2026-06-04"
unclass(d)
[1] 20608

A POSIXct is stored as seconds since the same reference moment, in UTC.

The lubridate package

lubridate is the tidyverse package for working with dates and times.

It is loaded with the tidyverse:

library(tidyverse)

Two main families: parsers that turn strings into dates, and accessors that pull pieces back out.

Parsing dates from strings

The function name tells you the order of year, month, day:

ymd("2026-06-04")
[1] "2026-06-04"
dmy("04/06/2026")
[1] "2026-06-04"
mdy("June 4, 2026")
[1] "2026-06-04"

Add _hms, _hm, or _h for date-times:

ymd_hms("2026-06-04 14:30:00")
[1] "2026-06-04 14:30:00 UTC"

today() and now()

today()
[1] "2026-05-20"
now()
[1] "2026-05-20 15:09:48 CEST"

today() returns a Date.

now() returns a POSIXct with your system’s time zone.

Extracting components

Function Returns
year() the year
month() the month (number, or label)
day() the day of the month
hour() the hour
minute() the minute
second() the second 
d <- ymd("2026-06-04")
year(d)
[1] 2026
month(d)
[1] 6
day(d)
[1] 4

month() with labels

d <- ymd("2026-06-04")
month(d, label = TRUE)
[1] Jun
12 Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < ... < Dec
month(d, label = TRUE, abbr = FALSE)
[1] June
12 Levels: January < February < March < April < May < June < ... < December

Day of week, day of year

d <- ymd("2026-06-04")

wday(d)
[1] 5
wday(d, label = TRUE)
[1] Thu
Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
yday(d)
[1] 155

wday() numbers weeks from Sunday by default. Use week_start = 1 to start on Monday.

Converting between types

as_date("2026-06-04 14:30:00")
[1] "2026-06-04"
as_datetime("2026-06-04")
[1] "2026-06-04 UTC"

as_date() drops the time.

as_datetime() lifts a date into a date-time at midnight UTC.

Time zones with with_tz()

with_tz() shows the same instant in another time zone:

t <- ymd_hms("2026-06-04 14:30:00", tz = "Europe/Zurich")
t
[1] "2026-06-04 14:30:00 CEST"
with_tz(t, "America/New_York")
[1] "2026-06-04 08:30:00 EDT"

Use force_tz() if you want to keep the clock reading the same and change the zone label, for example to fix data that was tagged with the wrong zone.

Date arithmetic

Subtracting two dates gives a duration:

ymd("2026-07-15") - ymd("2026-06-04")
Time difference of 41 days

Add days, weeks, or months with lubridate helpers:

ymd("2026-06-04") + days(10)
[1] "2026-06-14"
ymd("2026-06-04") + weeks(2)
[1] "2026-06-18"
ymd("2026-06-04") + months(1)
[1] "2026-07-04"

Displaying tables

Plain printing is not enough

By default, R prints a data frame as plain text:

starwars |>
  select(name, height, mass, species) |>
  head(3)
# A tibble: 3 × 4
  name           height  mass species
  <chr>           <int> <dbl> <chr>  
1 Luke Skywalker    172    77 Human  
2 C-3PO             167    75 Droid  
3 R2-D2              96    32 Droid

Fine while exploring, not what you want in a report or paper.

Two table packages

knitr::kable()

  • Already there with every Quarto setup
  • Quick, minimal, works in PDF and HTML
  • Few formatting options

gt::gt()

  • A grammar of tables, similar to ggplot
  • Rich formatting: spanners, footnotes, styles
  • Best output in HTML

For everyday reports, reach for kable(). For publication-quality tables in HTML, reach for gt.

knitr::kable()

starwars |>
  select(name, height, mass, species) |>
  head(4) |>
  knitr::kable()
name height mass species
Luke Skywalker 172 77 Human
C-3PO 167 75 Droid
R2-D2 96 32 Droid
Darth Vader 202 136 Human

The anatomy of a gt table

A gt table has named parts you can address one at a time:

  • table header: title and subtitle
  • column labels: the column headers
  • stub: a row-label column on the left
  • body: the data cells
  • footer: footnotes and source notes

A more polished gt table

starwars |>
  select(name, height, mass, species) |>
  head(4) |>
  gt() |>
  tab_header(
    title    = "Star Wars characters",
    subtitle = "First four rows"
  ) |>
  cols_label(
    name    = "Name",
    height  = "Height (cm)",
    mass    = "Mass (kg)",
    species = "Species"
  ) |>
  fmt_number(columns = c(height, mass), decimals = 1)
Star Wars characters
First four rows
Name Height (cm) Mass (kg) Species
Luke Skywalker 172.0 77.0 Human
C-3PO 167.0 75.0 Droid
R2-D2 96.0 32.0 Droid
Darth Vader 202.0 136.0 Human

Captions, labels, cross-references

Why label a table?

In a long document, you often write something like:

“See Table 2 for the breakdown by species.”

Quarto can number tables automatically and turn @tbl-species into “Table 2”, with a live link. You just need to label them properly.

Chunk options for a table

In any code chunk that produces a table, set two options:

```{r}
#| label: tbl-species
#| tbl-cap: "Average height by species"

starwars |>
  group_by(species) |>
  summarise(height = mean(height, na.rm = TRUE)) |>
  knitr::kable()
```
  • label must start with tbl- for Quarto to treat it as a table
  • tbl-cap is the caption text

Cross-referencing in text

In the document body, refer to the table with @tbl-species:

Average height differs noticeably between species
(see @tbl-species).

Quarto renders this as:

Average height differs noticeably between species (see Table 1).

Captions for gt tables

gt recognises the chunk’s tbl-cap option, so the same pattern works:

```{r}
#| label: tbl-starwars-gt
#| tbl-cap: "Star Wars characters"

starwars |>
  select(name, height, mass, species) |>
  head(4) |>
  gt()
```

Use the chunk options for the caption, not tab_header(), when you want Quarto to handle the numbering and the cross-reference.

Sub-captions for several tables

You can lay out several tables side by side with sub-labels:

```{r}
#| label: tbl-starwars
#| tbl-cap: "Star Wars summaries"
#| tbl-subcap:
#|   - "By species"
#|   - "By homeworld"
#| layout-ncol: 2

starwars |> count(species)   |> knitr::kable()
starwars |> count(homeworld) |> knitr::kable()
```

Cross-reference the pair with @tbl-starwars, or a single sub-table with @tbl-starwars-1.

A checklist for nice tables

  • Pick kable() for quick, lightweight tables
  • Pick gt() for tables that need careful formatting: titles, footnotes, or custom number formats
  • Always set label (starting with tbl-) and tbl-cap
  • Cross-reference with @tbl-..., never by typing “Table 2” by hand
  • Format numbers so the reader can compare them at a glance
